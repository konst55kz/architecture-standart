(Usability) |              |
| U1  | Интерфейс подачи заявки максимально удобен для клиента |              |
| U2  | Интерфейсы сайта и интернет-банка соответствуют дизайн-системе банка: привычные цвета, брендированные элементы |              |
| R   | Надёжность (Reliability)           |              |
| R1  | **[АЗТ]** Все сервисы работают 24/7 с доступностью 99,9%, включая интернет-банк |              |
| R2  | **[АЗТ]** При отказе ЦОД сервисы интернет-банка остаются доступны и выдерживают требуемую нагрузку |              |
| R3  | **[АЗТ]** В новом процессе интернет-банк не работает с АБС напрямую |              |
| R4  | **[АЗТ]** Заявки не теряются и не дублируются при сбоях и повторных отправках (гарантированная доставка, идемпотентная обработка) | Доп. Асинхронная обработка с повторами без идемпотентности приведёт к двойным заявкам и двойным депозитам |
| P   | Производительность (Performance)   |              |
| P1  | **[АЗТ]** Операции в интерфейсе выполняются за миллисекунды |              |
| P2  | **[АЗТ]** Справочные данные, включая ставки, загружаются меньше чем за 1 секунду | Справочники и ставки кешируются на стороне каналов и обновляются по событию из АБС. Решает и текущую проблему с загрузкой справочников при платежах |
| P3  | **[АЗТ]** Нагрузка от онлайн-заявок не угрожает работоспособности АБС | АБС масштабируется только вертикально, а её БД уже перегружена. Нужно выравнивание нагрузки: очередь и контролируемая скорость обработки на стороне АБС |
| P4  | **[АЗТ]** Новые сервисы масштабируются горизонтально, запросы распределяются между серверами, экземплярами приложений и ЦОД | Доп. Сервисы без состояния за балансировщиком нагрузки |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Разрабатывается документация для дальнейшего расширения системы | Спецификации API (OpenAPI), схемы событий Kafka, архитектурные решения |
| S2  | **[АЗТ]** Депозитный функционал интернет-банка выносится в отдельный микросервис | Даёт независимость от ядра подрядчика, совместимость с Kafka и первый шаг к микросервисной архитектуре интернет-банка |
| S3  | **[АЗТ]** Новый функционал разрабатывается и сопровождается командой банка без доработок ядра интернет-банка подрядчиком | Снижает зависимость от подрядчика и сроки изменений |
| +R  | + Ограничения (Restrictions)       |              |
| R+1 | **[АЗТ]** Трафик сайта и интернет-банка шифруется (TLS 1.2+, HTTPS) | Передаются персональные и финансовые данные |
| R+2 | **[АЗТ]** Максимально использовать технологии, которые уже есть в банке, включая СУБД MS SQL и Oracle |              |
| R+3 | **[АЗТ]** Новые технологии совместимы с текущими платформами разработки, и в банке есть экспертиза хотя бы на уровне языков программирования |              |
| R+4 | **[АЗТ]** Для очередей сообщений используется Kafka. Текущая платформа интернет-банка с Kafka несовместима | Интернет-банк вызывает депозитный микросервис по REST, а микросервис работает с Kafka |
| R+5 | **[АЗТ]** АБС масштабируется только вертикально из-за своей БД | Это ограничение определяет всю схему: синхронные вызовы АБС из онлайн-каналов недопустимы |

**[АЗТ]** — архитектурно значимое требование. **Доп.** — требование добавлено сверх полученной информации, обоснование дано в комментарии.
